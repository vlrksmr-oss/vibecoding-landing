# Журнал решений

## 2026-11-01 — Оставить пространство без языка и приложения

- Решение: создать только нейтральную техническую основу и не выбирать язык, фреймворк или архитектуру.
- Причина: содержание будущего проекта ещё не задано.
- Последствия: исходники, тесты и зависимости будут добавлены после конкретного задания.

## 2026-11-01 — Хранить секреты вне рабочего пространства

- Решение: использовать отдельный каталог пользователя за пределами проекта; абсолютный путь хранить только в исключённом `.local/paths.json`.
- Причина: не допускать попадания реальных секретов в проект и его историю Git.
- Последствия: чтение секретов приложением будет настроено после выбора технологии; каталог не считается зашифрованным.

## 2026-11-01 — Использовать локальную историю Git на ветке main

- Решение: создать отдельный локальный репозиторий с веткой `main` и тегом `bootstrap-v1` для технической основы.
- Причина: иметь локальную точку возврата без подключения внешних сервисов.
- Последствия: история Git не заменяет внешнюю резервную копию; глобальные настройки Git не изменяются.

## 2026-11-18 — Реализовать лендинг как автономный HTML

- Решение: использовать один статический `index.html` без сборщика, серверной части и сторонних зависимостей; ссылку MAX держать в одной настройке.
- Причина: в исходном пространстве не было приложения или выбранного стека, а для лендинга не нужна серверная обработка.
- Последствия: до публикации необходимо указать публичную HTTPS-ссылку на канал MAX. Страница сама не собирает данные, не проверяет подписку и не выдаёт курс.

## 2026-11-18 — Подготовить публикацию через GitHub Pages Actions

- Решение: развертывать только `index.html` через официальный GitHub Pages Actions workflow на push в `main`.
- Причина: сайт статический; пользователь выбрал публичный репозиторий `vlrksmr-oss/vibecoding-landing`.
- Последствия: публикация начнётся после создания репозитория и отправки кода; рабочий URL нужно подтвердить успешным выполнением workflow.
